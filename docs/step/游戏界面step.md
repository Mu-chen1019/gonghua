# 攻花 H5 项目游戏界面阶段步骤

## 1. 文档目标

- 本文档承接 `docs/step/开发阶段step.md` 后续工作，只记录对局内游戏画面、交互、手牌样式、玩家形象和背景表现的设计实现。
- 主页、个人页和移动端横屏通用页面体验放在 `docs/step/画面优化step.md`。
- 功能结构、联机和机器人能力放在 `docs/step/功能优化step.md`。
- 后续开发仍默认遵守根目录 `AGENTS.md`，规则口径优先参考 `docs/rules.md`。

## 2. 阶段 1：游戏画面设计实现

目标：让对局页从基础功能界面升级为清晰、稳定、有游戏感的实战画面。

任务：

- 重新梳理对局页信息层级：
    - 顶部状态区。
    - 玩家座位区。
    - 牌桌区域。
    - 当前玩家手牌区。
    - 动作按钮区。
    - 事件与排名区。
- 明确 PC、移动横屏、移动竖屏下各区域的优先级。
- 牌桌区域只展示对局所需元素，不在手牌和牌桌之间插入说明性内容。
- 将事件、日志、排名等辅助信息放到侧边或可收起区域。
- 设计游戏结束、排名产生、只出不添、封攻、收牌阶段的视觉状态。
- 保证所有布局尺寸有稳定约束，避免卡牌、按钮、事件内容变化导致整体跳动。

完成标准：

- 对局页第一屏能直接完成出牌、防守、停攻、放弃防守和确认收牌。
- 玩家不用阅读额外说明也能判断当前阶段和自己能否操作。
- 桌面牌位关系清晰，攻牌和守牌不会混淆。

测试重点：

- PC 和移动横屏截图检查。
- 牌桌牌位增多时不重叠。
- 事件、排名和提醒不遮挡手牌与桌面牌。

## 3. 阶段 2：游戏内交互操作设计

目标：让出牌、防守、换位、排序和机器人推进都具备稳定可预期的操作体验。

任务：

- 完善拖拽交互：
    - 手牌拖到桌面出攻牌。
    - 手牌拖到攻牌位出守牌。
    - 已出的守牌拖到其他攻牌位做移动或换位。
    - 非法动作回退到原状态并给出非阻塞提醒。
- 完善点击交互：
    - 保留按钮方式作为拖拽失败或触屏不便时的备用入口。
    - 动作失败使用即时提醒，不要求玩家点击确认。
- 完善可投放区域反馈：
    - 当前可投放牌位高亮。
    - 不可投放区域弱化。
    - 拖动浮层不遮挡目标牌位。
- 完善机器人过程展示：
    - 机器人每步动作按固定延迟展示。
    - 机器人选择事件和实际动作事件都进入事件栏。
    - 机器人手牌变化即时可见。
- 完善手牌排序交互：
    - 一键排序按钮。
    - 自动排序配置。
    - 自定义拖动排序。

完成标准：

- 鼠标和触屏都能完成核心动作。
- 拖拽失败不会破坏本地手牌顺序和服务端状态。
- 机器人动作过程可观察，不会瞬间跳过关键状态。

测试重点：

- 拖拽出牌、拖拽守牌、拖拽移动守牌路径。
- 非法换位、非法防守、非法加攻提醒。
- 自动排序和手动排序切换后手牌顺序稳定。

## 4. 阶段 3：手牌样式设计实现

目标：统一真人手牌、机器人手牌、桌面牌和拖拽浮层的牌面样式。

任务：

- 统一卡牌组件视觉：
    - 点数固定在左上角。
    - 花色保持居中或现有主视觉位置。
    - 主牌、大小王、普通牌有可识别差异。
    - 紧凑模式和标准模式共享同一组件。
- 优化当前玩家手牌：
    - 鼠标经过上浮不被容器裁切。
    - 选中态清晰。
    - 横向滚动或堆叠不影响拖拽。
    - 移动端触屏点击区域足够。
- 优化机器人手牌：
    - 默认按一键排序规则排序。
    - 不换行展示。
    - 超出自身面板时横向滚动。
    - 牌面可适当缩小或堆叠，但必须完整可查看。
- 优化桌面牌：
    - 桌面牌和手牌样式保持一致。
    - 攻牌、守牌位置关系稳定。
    - 密集牌位时可以缩放或换行，但不得遮挡。

完成标准：

- 所有牌面来源都使用统一视觉语言。
- 玩家能快速识别牌点、花色、主牌和大小王。
- 手牌和桌面牌在不同尺寸下不出现裁切或错位。

测试重点：

- 手牌数量多时的滚动和堆叠表现。
- 机器人手牌超出面板时滚动条可用。
- 拖拽浮层和原牌位置不会造成布局跳动。

## 5. 阶段 4：玩家形象设计优化

目标：让玩家座位、身份、角色、状态和排名更直观。

任务：

- 设计玩家头像或形象占位：
    - 真人玩家。
    - 机器人玩家。
    - 已完成玩家。
    - 当前可操作玩家。
- 优化玩家状态展示：
    - 主攻。
    - 受攻。
    - 助攻。
    - 已停攻。
    - 已完成排名。
    - 当前行动提示。
- 优化机器人展示：
    - 机器人等级标识预留。
    - 机器人思考中状态。
    - 机器人动作延迟期间的轻量反馈。
- 优化排名展示：
    - 已完成玩家在座位区保留名次。
    - 右侧排名列表与事件栏不混淆。
    - 游戏结束时排名结果更突出。

完成标准：

- 玩家身份和角色不用阅读长文本即可识别。
- 当前可操作对象清晰，但不误导为只有一个玩家能操作。
- 已完成玩家不再参与轮转的状态清楚。

测试重点：

- 真人、机器人、已完成玩家状态组合。
- 多名玩家同时可操作时的展示。
- 排名产生后的座位区和侧边区一致。

## 6. 阶段 5：游戏界面背景设计实现

目标：在不影响可读性和性能的前提下，建立符合攻花牌局氛围的背景视觉。

任务：

- 设计牌桌背景：
    - 牌桌区域与页面背景有明确层级。
    - 背景不干扰卡牌点数和花色识别。
    - 不使用过度装饰导致小屏拥挤。
- 设计整体页面背景：
    - PC 和移动端都保持清晰。
    - 避免单一深色或单一渐变占满全页。
    - 可考虑轻量纹理、桌面材质或场景化背景。
- 设计状态氛围：
    - 封攻。
    - 只出不添。
    - 游戏结束。
    - 当前玩家胜出。
- 控制性能：
    - 背景资源体积可控。
    - 动画不影响拖拽和出牌。
    - 低性能设备可以关闭复杂背景。

完成标准：

- 背景增强游戏感，但不影响核心操作。
- 卡牌、按钮和文本在背景上保持足够对比度。
- 移动横屏下背景不会挤占对局空间。

测试重点：

- PC、移动竖屏、移动横屏截图检查。
- 背景加载失败时页面仍可正常使用。
- 拖拽操作期间帧率和响应正常。
